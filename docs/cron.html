Part 1 · Cron

Anatomy of a crontab line

Every cron entry is five time fields, then the command to run. All five must match the current minute for the job to fire.

*****command to run 
│ │ │ │ │
│ │ │ │ └─ day of week (0–7, both 0 and 7 = Sunday)
│ │ │ └─── month (1–12)
│ │ └───── day of month (1–31)
│ └─────── hour (0–23)
└───────── minute (0–59)

Cron's shell is not your shell

This is the #1 source of "works when I run it, fails in cron." Cron jobs run non-interactive, non-login — see the bottom-right cell of the mode grid on the bash vs zsh page: no .bashrc, no .profile, a bare-bones PATH (often just /usr/bin:/bin).

SymptomFix
"command not found"use full paths (/usr/bin/python3) or set PATH= at the top of the crontab
script works manually, not in crondon't rely on aliases, functions, or shell rc files — source what you need explicitly
no output visibleredirect: * * * * * cmd >> /var/log/cmd.log 2>&1
too many "cron sent mail" emailsset MAILTO="" at the top, or redirect output instead
Part 2 · bash · awk · sed

Three tools, three jobs

A cron entry almost always ends up calling one of these — or all three chained with pipes.

bash

the glue — control flow, orchestration
if [ -f "$lock" ]; then
  exit 0
fi
touch "$lock"
./backup.sh && rm "$lock"

awk

the columns — pattern → action over fields
awk -F, '$3 > 100 {
  sum += $3
} END { print sum }' sales.csv

sed

the stream editor — line-by-line find & replace
sed -i 's/DEBUG/INFO/g' app.log
sed -n '10,20p' access.log

Same task, three ways

Print the 2nd column of a space-separated file
bash
while read -r a b _; do
  echo "$b"
done < file.txt
awk
awk '{print $2}' file.txt
sed
sed -E 's/^\S+\s+(\S+).*/\1/' file.txt
Replace "staging" with "production" everywhere in a file
bash
content=$(< file.txt)
echo "${content//staging/production}" > file.txt
awk
awk '{gsub(/staging/,"production")
print}' file.txt > tmp && mv tmp file.txt
sed
sed -i 's/staging/production/g' file.txt
Sum a column of numbers
bash
sum=0
while read -r n; do
  (( sum += n ))
done < nums.txt
echo "$sum"
awk
awk '{s+=$1} END{print s}' nums.txt
sed
— sed has no arithmetic;
wrong tool for this job
💡 In a real cron job these are usually chained: bash checks a lock file and sets up the environment, pipes a log through sed to strip noise, then through awk to total up a column, and bash mails or logs the result. None of them replace the others — pick the tool that matches the shape of the data: whole program → bash, columns/aggregation → awk, line-level text surgery → sed.
